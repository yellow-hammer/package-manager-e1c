# Задачи

Сценарии автоматизации на OneScript. Запускаются из корня репозитория.
Всё держится внутри экосистемы 1С: `oscript`, `vrunner`, `vanessa-automation`,
`YAxUnit`. Служебных скриптов на других языках в проекте нет.

| Сценарий | Назначение |
| -------- | ---------- |
| `check-all.os` | Полная проверка перед сдачей: формат, тесты, синтакс-контроль, BDD |
| `run-tests.os` | Сборка с тестами, загрузка в базу, прогон YAxUnit, разбор отчёта |
| `build-test-extension.os` | Наложение модульных тестов на копию решения |
| `normalize-sources.os` | Приведение `.bsl` и `.xml` к формату выгрузки Конфигуратора |
| `sync-ci-templates.os` | Перенос шаблонов из `templates/ci/` в макеты расширения |

Обычная работа — одна команда:

```bash
oscript tasks/check-all.os
```

Без сценарных тестов, когда нужен быстрый круг:

```bash
oscript tasks/check-all.os --no-bdd
```

## Почему `run-tests.os`, а не голый vrunner

YAxUnit возвращает нулевой код возврата и тогда, когда тестовый модуль не
смог скомпилироваться: такой модуль молча выпадает из прогона, а отчёт
остаётся зелёным. На этом дважды попались модули, использовавшие
`ТаблицаЗначений` в клиентском контексте.

`run-tests.os` после прогона сверяет отчёт со списком модулей на диске и
читает лог на ошибки загрузки. Модуль без набора в отчёте — провал с
указанием причины из лога.

## Почему `normalize-sources.os`

Конфигуратор выгружает `.bsl` и `.xml` в UTF-8 с BOM и CRLF. Файл,
отредактированный сторонним инструментом, даст шумный diff при следующей
выгрузке. Режим `--check` ничего не меняет и возвращает 1 при расхождении —
для сборочной машины.

```bash
oscript tasks/normalize-sources.os --check
```
