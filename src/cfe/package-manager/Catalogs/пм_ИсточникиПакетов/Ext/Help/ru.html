Справочник хранит каталоги пакетов. Одна строка — это один проект у провайдера, в котором лежит манифест каталога и реестр пакетов с файлами.

Источник заводится один раз. Дальше новые пакеты и версии появляются в менеджере сами, вручную ссылки на каждый пакет прописывать не нужно.

Режим каталога и режим одного пакета

  • Если заполнен Файл каталога (по умолчанию packages.json), список пакетов читается из этого манифеста.
  • Если Файл каталога оставить пустым, источник работает в режиме одного пакета. Тогда обязательно заполнить Имя пакета.

Публичный источник: без токена

Для публичного проекта поле Токен доступа оставьте пустым. Никакой настройки прав не требуется.

Приватный источник: с токеном

Для приватного проекта нужен токен с минимально необходимыми правами.

  • GitLab: Project Access Token, если доступ нужен к одному проекту, или Personal Access Token, если к нескольким.
  • Требуемая область: read_api. Права на запись выдавать не нужно — менеджер только читает.
  • Где создать: проект → Settings → Access Tokens, либо пользователь → Preferences → Access Tokens.

Обращение с токеном

  • Поле Токен доступа отображается в замаскированном виде, введенное значение на экране не видно.
  • Токен нельзя хранить в коде, в шаблонах CI, в README и в журналах.
  • Токен нельзя отправлять в техническую поддержку, включать в коммиты и показывать на скриншотах.
  • Если токен скомпрометирован, отзовите его у провайдера и создайте новый.

Заполняется автоматически

  • ID проекта — кэш идентификатора, определяется при первом обращении. При смене сервера, пути проекта или провайдера сбрасывается.
  • Текст ошибки — последняя ошибка обращения к источнику.
