Справочник хранит проекты у провайдера. Одна строка — это один проект, из которого берутся пакеты и версии.

Источник заводится один раз. GitLab читает Generic Package Registry, GitHub — Releases того же репозитория. Вручную ссылки на каждый пакет прописывать не нужно.

Фильтр по имени пакета

Поле Имя пакета необязательно. Если его заполнить, из проекта берется только этот package. Если оставить пустым, в менеджере видны все пакеты проекта.

Публичный источник: без токена

Для публичного проекта поле Токен доступа оставьте пустым. Никакой настройки прав не требуется.

Приватный источник: с токеном

Для приватного проекта нужен токен с минимально необходимыми правами.

  • GitLab: Project Access Token, если доступ нужен к одному проекту, или Personal Access Token, если к нескольким. Область: read_api.
  • GitHub: токен с правом чтения репозитория. Для fine-grained достаточно Contents: Read, для classic — repo на приватный проект.
  • Права на запись выдавать не нужно — менеджер только читает.
  • Где создать: проект или пользователь → настройки → Access Tokens.

Обращение с токеном

  • Поле Токен доступа отображается в замаскированном виде, введенное значение на экране не видно.
  • Токен нельзя хранить в коде, в шаблонах CI, в README и в журналах.
  • Токен нельзя отправлять в техническую поддержку, включать в коммиты и показывать на скриншотах.
  • Если токен скомпрометирован, отзовите его у провайдера и создайте новый.

Заполняется автоматически

  • ID проекта — кэш идентификатора, определяется при первом обращении. При смене сервера, пути проекта или провайдера сбрасывается.
  • Текст ошибки — последняя ошибка обращения к источнику.
