# Тесты

Три уровня, каждый ловит свой класс ошибок.

| Уровень | Инструмент | Что ловит | Где лежит |
| ------- | ---------- | --------- | --------- |
| Синтакс-контроль | `vrunner syntax-check` | Несуществующие имена и методы во всех контекстах | — |
| Модульные | YAxUnit | Логику модулей, целостность метаданных, построение форм | `tests/cfe/package-manager-tests` |
| Сценарные | Vanessa Automation | Работу через интерфейс: нажатия, сообщения, списки | `features/` |

Разделение не формальное. Синтакс-контроль не видит имён, которые платформа
разбирает в момент выполнения: несуществующий параметр условного оформления
он пропускает. Модульный тест не нажимает кнопку. Сценарный тест не заглянет
в перечисление метаданных. Каждый из трёх уровней в этом проекте уже поймал
то, что два других пропустили.

## Одна команда

```bash
oscript tasks/check-all.os
```

Порядок внутри: формат исходников → модульные тесты → загрузка чистого
решения → синтакс-контроль → сценарии. Модульные тесты грузят отдельное
расширение `package-manager-tests`. После них `package-manager` снова
берётся из `src`, поэтому синтакс-контроль и BDD проверяют ровно то,
что уйдёт пользователю.

## Где что лежит

| Каталог | Расширение в базе | Что это |
| ------- | ----------------- | ------- |
| `src/cfe/package-manager` | `package-manager` | Решение, поставка |
| `tests/cfe/package-manager-tests` | `package-manager-tests` | Наши модульные тесты |
| `tests/cfe/yaxunit` | `YAXUNIT` | Движок YAxUnit 25.12 |

Тесты не подмешиваются в решение. Отбор YAxUnit — `package-manager-tests`
в `tools/yaxunit.json`.

## Контексты: почему прогон идёт на тонком клиенте

YAxUnit различает серверные и клиентские тесты. Клиент-серверный общий модуль
компилируется в обоих контекстах, и серверное имя внутри него ломает только
клиентскую компиляцию — серверный прогон такую ошибку не увидит.

Толстый клиент видит серверные типы и потому тоже её пропускает. Тонкий —
нет, поэтому прогон идёт с `--ordinaryapp false`.

| Модуль тестов | Контекст | Тестов | Предмет |
| ------------- | -------- | ------ | ------- |
| `пмТест_Адреса` | клиент + сервер | 4 | Нормализация адреса и пути проекта, умолчания |
| `пмТест_ВерсииПакетов` | клиент + сервер | 11 | Разбор, сравнение версий, фильтр по типу релиза |
| `пмТест_Формы` | клиент | 5 | Каждая форма расширения строится без ошибок |
| `пмТест_СортировкаВерсий` | сервер | 2 | Сортировка таблицы версий |
| `пмТест_ИсточникиПакетов` | сервер | 8 | Умолчания, нормализация при записи, сброс кэша ID |
| `пмТест_ШаблоныПубликации` | сервер | 9 | Подстановки в шаблонах CI, отсутствие секретов |
| `пмТест_Смоук` | сервер | 7 | Объекты, подсистема, роли, регламентное задание, макеты |
| `пмТест_УстановленныеПакеты` | сервер | 7 | Запись и отбор сведений, разделение по источникам |
| `пмТест_Провайдеры` | сервер | 14 | Диспетчеризация провайдеров, контракт GitLab и GitHub |
| `пмТест_ТипыФайлов` | сервер | 10 | Тип файла пакета, выбор файла версии |

Итого 92 прогона: тесты в двух контекстах считаются дважды.

Сети в модульных тестах нет намеренно: прогон не должен зависеть от
доступности внешнего сервиса и упираться в таймауты.

## Развернуть базу

Базовая конфигурация — заглушка `src/cf`. В её модулях объявлены пустые
`ПриНачалеРаботыСистемы` и `УстановкаПараметровСеанса`: к ним подключаются
расширения через `&После(...)`. Без этих обработчиков движок YAxUnit не
получает управление, а сеанс падает с невосстановимой ошибкой.

```bash
vrunner init-dev --settings env.json
```

```bash
vrunner compileext src/cfe/package-manager package-manager --updatedb --settings env.json
vrunner compileext tests/cfe/package-manager-tests package-manager-tests --updatedb --settings env.json
vrunner compileext tests/cfe/yaxunit YAXUNIT --updatedb --settings env.json
```

**Снимите у YAXUNIT безопасный режим и защиту от опасных действий** —
иначе движок не сможет писать отчёт:

```bash
ibcmd infobase config extension update --db-path=build/ib --name=YAXUNIT --safe-mode=no --unsafe-action-protection=no
```

## Прогон по отдельности

Модульные — со сверкой отчёта со списком модулей:

```bash
oscript tasks/run-tests.os
```

Голый прогон, если база уже готова:

```bash
vrunner run --command "RunUnitTests=./tools/yaxunit.json" --settings env.json --ordinaryapp false
```

Отчёт jUnit — `build/out/yaxunit/junit.xml`, код возврата —
`build/out/yaxunit/result.txt`, лог — `build/out/yaxunit/log.txt`.
**Ошибки инициализации модулей видны только в логе**, на код возврата они
не влияют.

Тесты идут **в транзакции**, поэтому созданные ими источники и записи
регистра в базе не остаются.

Сценарные:

```bash
vrunner vanessa --settings env.json
```

Отчёт — `build/out/vanessa/junit`, статус — `build/out/vanessa/bdd-exit-code.log`.

Синтакс-контроль:

```bash
vrunner syntax-check --settings env.json
```
